# Veyon GPO Deployment — практический проект PowerShell

[English README](README.md) · [История версий на русском](CHANGELOG.ru.md)

Проект документирует эволюцию скрипта развёртывания **Veyon Service 4.11.3** через **GPO → Scheduled Task (SYSTEM) → PowerShell**. Кейс основан на реально предоставленных версиях v1.0–v1.3. Важны не только успешная установка, но и обеспечение корректного firewall, проверка подписи/хешей, исключение параллельного запуска и восстановление после ошибки.

## Структура

- `scripts/Install-Veyon.ps1` — обезличенная v1.3; **не запускается без заполнения и проверки параметров**.
- `scripts/Veyon-Diagnostics.ps1` — диагностика без изменения целевых настроек.
- `history/` — обезличенные учебные снимки v1.0–v1.3, чтобы изучить реальные изменения. **Не использовать для самостоятельного production-развёртывания.**
- `examples/manifest.example.json` — структура manifest; хеши в нём недействительны.
- `examples/config.example.json` — только схема проверяемых параметров Veyon, **не** полноценный экспорт для `config import`.
- `docs/gpo-setup.md` — требования, диагностика и особенности эксплуатации.

## Как работает

```text
GPO / Group Policy Preferences
        ↓
Scheduled Task под LOCAL SYSTEM
        ↓
Сценарий PowerShell
        ↓
NETLOGON: манифест, EXE, Veyon config
        ↓
SHA256 + Authenticode + копирование в локальный кеш
        ↓
Veyon Service + TCP/11100 с разрешёнными источниками
        ↓
Проверка версии, службы, конфигурации, firewall
```

Поддерживаемая область пилота — **Windows 10/11 Workstations**, не серверы и не контроллеры домена. Используется `/S /NoMaster`, то есть Master не устанавливается. Скрипт не выполняет автоматическое обновление любой существующей версии: несовпадение обнаруженной версии с 4.11.3 приводит к отказу до ручного анализа.

## Перед использованием

1. Ввести собственные проверенные SHA256 дистрибутивов x64/x86 и конфигурации, согласовать manifest.
2. Задать доступный только доверенным администраторам репозиторий и безопасные права записи на его содержимое.
3. Проверить сертификат производителя установщика, параметры Veyon Config и группу операторов.
4. Заменить демонстрационные диапазоны RFC 5737 на утверждённые административные IP/подсети.
5. Проверить GPO Security Filtering, OU, права компьютерных учётных записей на NETLOGON и выполнение Scheduled Task от SYSTEM.
6. Провести пилот и обязательный отрицательный тест доступа неавторизованного оператора.

**Предупреждение:** `-WhatIfCheck` — собственный режим проверки, а не гарантированно безвредный native `-WhatIf`: могут создаваться локальные каталоги и изменяться их ACL. После сбоя TCP/11100 может остаться заблокированным специально; не удаляйте блокировку без выяснения причин.

В репозитории **нет исходной производственной конфигурации**, внутренних доменов, адресов, реальных SHA256 и бинарных дистрибутивов Veyon. Архивные версии адаптированы и не побайтово совпадают с исходниками.
